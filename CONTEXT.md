# Finance Intelligence Dashboard

A household budgeting and net-worth app that syncs bank transactions (via Plaid) and investment
holdings (via SnapTrade), lets a user categorize spend into their own budget envelopes, and
reconciles what actually left the account against what got budgeted. This is a first draft —
terms and boundaries here should be corrected by whoever owns the domain model next.

## Language

**Transaction**:
A single posted or pending bank-side money movement, one row per Plaid sync/import event, with a
signed amount in cents (negative = money out, positive = money in). Distinct from a `portfolio_transaction`
(buy/sell/dividend on the investment side), which has different sign conventions and is not stored
in cents.
_Avoid_: using "transaction" for investment activity — that's a Portfolio Transaction.

**Split**:
A row that reassigns part of one transaction's amount to a different Envelope. When a transaction
has any splits, they fully replace its own category/amount for budget purposes — splits must sum
to the parent transaction's amount; there is no partial-split state.
_Avoid_: "partial category" — the model is all-or-nothing once split.

**Envelope**:
The canonical budget bucket: a named spending target (`monthlyTarget`) with matcher rules used to
auto-categorize transactions into it. Envelopes are referenced by name (string), not by foreign
key, so a transaction survives an envelope rename.
_Avoid_: "Category" as a synonym for the envelope itself — Category is the string label; Envelope
is the row carrying a target and rules. They're related but not the same concept.

**Category**:
The string label naming an envelope, stored redundantly on transactions, splits, and learned
rules. Not a separate object with its own identity — it's how transactions/rules point at an
Envelope by name.

**Envelope proposal**:
A derived, never-auto-applied suggestion generated by clustering the user's own transaction
history (seed rules are only a clustering hint). Only categories the user actually has spending in
are proposed. Reflects a standing principle: envelope sets are proposed, never imposed as a fixed
taxonomy.

**Allocation**:
A row overriding an envelope's standing `monthlyTarget` for one specific (year, month). If no
allocation exists for that month, the envelope's `monthlyTarget` is the effective budgeted amount.
_Avoid_: conflating with Reallocation, which is a different operation (see below).

**Reallocation**:
Moving budgeted dollars from one envelope to another for a single month without changing the
total budgeted — a conservation-rule operation where the "from" envelope loses exactly what the
"to" envelope gains.

**Bank Account**:
An account (chequing/savings/credit/manual) belonging to a Bank Connection (a Plaid item), the
source of Transactions and Balance Snapshots. Modeled as an entirely separate table family from
investment accounts — there is no shared polymorphic "account" abstraction.
_Avoid_: using "Account" alone when it's ambiguous whether you mean bank or investment side.

**Portfolio**:
The investment side of the app, modeled independently of bank accounts: a Wealthsimple
Connection (via SnapTrade) produces Portfolio Snapshots, each a point-in-time total across
account types (e.g. TFSA, RRSP, non-registered, crypto), which in turn own Holdings and Portfolio
Transactions. Portfolio money fields are fractional (not integer cents) since they represent
share quantities, prices, and estimated values rather than settled cash.

**Holding**:
A position (quantity, cost basis, market value, optional broker-reported unrealized P&L) as of one
Portfolio Snapshot — a child of the snapshot, not a standalone per-account record over time.

**Balance**:
The current balance on a Bank Account, overwritten on every Plaid sync.
_Avoid_: confusing with Balance Snapshot — Balance is the live/current value; Snapshot is history.

**Balance Snapshot**:
An append-only daily historical record of a Bank Account's balance fields — the banking-side
analog of a Portfolio Snapshot. Not backfillable, and the sole source for the bank side of the
Net Worth series over time.

**Net Worth**:
A daily series computed on the fly (not stored) by combining bank-side balances — carried forward
from the latest applicable Balance Snapshot, with credit-type accounts counted as a negative/
liability — plus portfolio total value, with an explicit rule excluding Wealthsimple "mirror" bank
accounts so the same cash isn't counted on both the bank and portfolio sides. _Inferred, not
directly confirmed in code: the exact mirror-exclusion logic was not read in full — only its
calling comment was._

**Outflow**:
The sum of all money that left the account — every negative transaction plus refunds netted the
same way — computed independently of envelope categorization. This is the figure any UI surface
labelled "Spent" must show, and the one used to compute saved amount (`income − outflow`).
_Avoid_: "Spent" as a synonym for Outflow — see Spend below; using Spend where the standing product
rule requires Outflow silently treats every uncategorized dollar as if it were saved.

**Spend** (`totalSpent`):
The sum of only the spend that landed in a real Envelope — it shrinks as categorization coverage
gets worse and does not include the uncategorized remainder (`unattributedSpent`). `outflow −
unattributedSpent === spend` is meant to hold as a checkable identity.
_Avoid_: labelling a "Spent" surface with this figure instead of Outflow.

**Transfer**:
A transaction moving money between the user's own accounts, marked via a `transferSource` of
"rule" or "manual." Transfers are excluded from both income and spend everywhere in budget
calculations. Marking is driven by user-approved transfer patterns (substring match against a
normalized description), seeded with suggestions but never auto-applied.

**Refund**:
A positive, envelope-attributed transaction classified as one of: pure income (the merchant has
no outflow history at all), a matched refund (paired against a same-amount purchase within a
lookback window, counted in the purchase's month), or an unmatched/fallback refund (counted in its
own landing month). A refund nets as negative spending against its envelope — it is never counted
as income.
_Avoid_: treating a refund as generic income; the netting behavior is the whole point of the term.

**Learned Rule**:
A pattern-to-envelope mapping saved when a user corrects a categorization or accepts a "make this
a rule?" proposal, optionally scoped to one account and/or a start date, and takes precedence over
shipped seed rules regardless of specificity. Distinct from Categorization Event, an append-only
log of every manual correction/rule-save kept because it can't be reconstructed after the fact.
_Avoid_: "recurring rule" — this term does not appear in the codebase; the object is a Learned
Rule.

**Categorization Event**:
An append-only, never-updated log entry recording a manual categorization correction or rule
approval, kept separately from Learned Rule because the training history can't be reconstructed
after the fact.

**Connection Status**:
Each external connection (Bank, Wealthsimple/SnapTrade, Spreadsheet) carries its own status enum
with provider-specific verbs that are not interchangeable: bank connections use
active/relink_required/error, Wealthsimple connections use active/reconnect_required, spreadsheet
connections use active/reauth_required.
_Avoid_: treating "relink," "reconnect," and "reauth" as synonyms across providers — each is a
distinct enum value on a distinct table.

**Cents** (money seam):
The storage representation for ledger money columns (bank balances, transaction/split amounts,
envelope target, allocation) — integer cents in the database, converted to/from dollars at the
single conversion seam so callers above the database layer always work in dollars. Uses a
documented "half away from zero" rounding rule evaluated on the decimal string, not naive
floating-point rounding. Portfolio columns (share quantities, prices, valuations) are deliberately
excluded from this seam since they're fractional/estimated, not settled cash.
_Avoid_: assuming every money-shaped column is in cents — only the columns enumerated in the
money-columns list are.
